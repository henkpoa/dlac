# Divine Elements (AscensionXI Paladin)

**Status, 2026-10-25:** built on branch `claude/pld-divine-guard` (PR #225, draft), on the owner's
client for playtest; not merged. Tests: `tests/ascensionxi_divine_elements.lua` (49 checks). It
needs no server change: the server half is AscensionXI PR #1054 (Divine Fury,
`modules/custom/lua/pld_divine_fury.lua`), whose design record is
`documentation/custom/pld-divine-guard.md` section 8 in that repo.

## What it is

In Divine Fury an AscensionXI Paladin charges the next weapon skill with divine elements, one
point each. Each element adds its own level 1 skillchain property, and the level 2 property it
makes with an element the weapon skill already has: a level 2 property is a pair of elements
(Fusion = Fire + Light, Fragmentation = Wind + Lightning, Gravitation = Earth + Dark, Distortion =
Water + Ice). From level 50 the weapon holds two elements, which also pair with each other. The
chains addon shows what closes the chain standing on your target; the owner asked for a dlac
window that "would tell you what SC elements you have ready and what you need to build others"
(2026-10-25).

The **Divine Elements** Job helper (`jobhelpers\pld\divine-elements`) is that window:

```
Divine Elements  2 points
Holding Dark
  Crescent Moon:  Gravitation, Compression
  Freezebite, Power Slash, Spinning Slash:  Compression

Fusion
  Power Slash + Fire              1 point
  Any WS + Fire + Light           2 points
Fragmentation
  Spinning Slash                  has it
  Freezebite + Lightning          1 point
  Any WS + Wind + Lightning       2 points
Gravitation
  Crescent Moon + Dark            ready
  Any WS + Earth + Dark           1 point
Distortion
  Freezebite + Water              1 point
  Any WS + Ice + Water            2 points

Light: Fusion meets Fragmentation. Darkness: Gravitation meets Distortion.
```

- **Holding:** the elements on the weapon now (from their buff icons), and what they add to each
  of your weapon skills, grouped by answer.
- **Build:** for each level 2 property, cheapest first: the weapon skills that have it of their
  own, a weapon skill plus one element (the weapon skills that already have its partner), and any
  weapon skill plus both elements (only from level 50). The cost counts only the elements you do
  not hold yet. What you hold already reads **ready** in green; what costs more points than you
  have is dimmed.
- The Panel repeats the window and lists each element's level 1 property.

"Your weapon skills" are the ones the client lists for the weapon in your hands. The window shows
while your main job is Paladin, Divine Fury is up (buff 655) and the divine elements are in your
Job Abilities menu (Divine Fire, client record 929, which the server lists only once learned and
only in Divine Fury). It hides with the game HUD, can be dragged (its place is remembered once the
drag settles), locked, or switched off. The module never acts: no commands, no keys, no gear.

## Where the answers come from

| Answer | Source |
|---|---|
| Stance and held elements | the client's buff list: 655 Divine Fury, 660-667 Divine Fire to Divine Dark |
| Learned | `HasAbility(929)`: the server lists the element abilities only once learned, in Divine Fury |
| Your weapon skills | `HasWeaponSkill(id)` over `data/weaponskills.lua`; the client resource name when it has one |
| Each weapon skill's properties | `data/weaponskills.lua`, generated from AscensionXI's `sql/weapon_skills.sql` by that repo's `python tools/dlac-weaponskills.py <dlac checkout>` (names from its chains addon) |
| Points | the pack's `pldGauge` service (`servers/ascensionxi/modules/pldgauge`), its `view().points` while synced; unknown when the gauge is hidden, and then nothing is dimmed |
| Level | `S.player.level()` (the sync-aware level) |
| The rule | `rules.lua`, a copy of the server's `pf.addedProperties` |

The level 50 "two elements" quest is invisible to the client, so the two-element rows show from
level 50 regardless, as in the chains addon.

## Files

| File | Role |
|---|---|
| `jobhelpers/pld/divine-elements/rules.lua` | Pure: the element tables, `added` (the server's rule), `held`, and `plan` (the window's answers) |
| `jobhelpers/pld/divine-elements/init.lua` | The Job helper: the client reads (one seam, `_client`), the Panel, the window |
| `jobhelpers/pld/divine-elements/data/weaponskills.lua` | Generated by the AscensionXI repo's `tools/dlac-weaponskills.py` (dlac's own `tools/` is untracked): every player weapon skill and its properties, as the server has them |
| `servers/ascensionxi/features.lua` | `jobhelpers` lists `divine-elements` beside `dnc-status` |
| `tests/ascensionxi_divine_elements.lua` | Headless suite |

## Verification

- `lua tests/ascensionxi_divine_elements.lua`: the server's element rule on its own cases
  (Crescent Moon + Dark, Spinning Slash + Fire + Light, Earth + Dark on a Fusion weapon skill, a
  weapon skill's own pair adding nothing, Torcleaver's level 3 elements), held elements from the
  icons, the generated table, the plan's rows and their order, costs, ready and dimming, no
  two-element rows below 50, the module contract and the pack allowlist, when the window shows,
  and the drawn lines.
- `lua tests/ascensionxi_pldgauge.lua`, `tests/ascensionxi_dncstatus.lua`,
  `tests/ascensionxi_fishing.lua` and `tests/smoke_ui.lua` still pass.

Owed, in the client: the window appears in Divine Fury with the elements learned and disappears
in Divine Guard; the held elements and the ready rows follow Divine Fire to Divine Dark as they
are used; the points match the gauge; the weapon skill list follows a weapon swap.

## Next

When the server regenerates `weapon_skills.sql` or a weapon skill changes its properties, run
`python tools/dlac-weaponskills.py <dlac checkout>` in the AscensionXI repo again. If the elements' rule changes on the server (`pf.addedProperties`), change
`rules.added` with it; its cases in the suite are the server's own (`scripts/tests/jobs/pld/divine_fury.lua`
PF-02).
